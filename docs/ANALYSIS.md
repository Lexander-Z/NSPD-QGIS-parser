# Разбор скриптов NSPD v6.2

Рабочий документ: что в репозитории продублировано, что сломано или хрупко,
в каком порядке это чинится и почему. Разбор сделан по шести файлам
`NSPD v6.2 *.py` и README.md в состоянии коммита `a13a49b`.

Важное ограничение: разбор сделан чтением кода. QGIS в среде, где готовился
документ, нет, поэтому ни один пункт ниже не проверялся кликом по карте.
Там, где вывод зависит от поведения QGIS или сервера НСПД, это сказано явно.

## 2. Найденные проблемы

Порядок внутри раздела: сначала то, что ломает работу, потом то, что тихо
теряет данные, потом неудобства. Для каждого пункта указано, при каких
действиях пользователя или входных данных он проявляется.

### 2.1. Опечатка в коде слоя «ЗОУИТ природных территорий» — сломано

Подтверждено (сверх списка из задания). В `NSPD v6.2 ЗОУИТ природных
территорий.py` стоит `layer_code = "37580/wms"`. Код подставляется в
`LAYERS=` и `QUERY_LAYERS=`, поэтому запрос уходит с
`LAYERS=37580/wms&QUERY_LAYERS=37580/wms`. Слоя с таким именем на
сервере нет, и этот скрипт не может вернуть ни одного объекта, где бы
пользователь ни кликнул. Что именно отвечает НСПД (ошибку WMS или пустую
коллекцию), без доступа к серверу не проверить. Но корректного ответа на
такой запрос быть не должно.

### 2.2. Импорт `shapely` — падение до первого клика

Подтверждено. В строке 3 стоит `from shapely.geometry import shape`. `shapely` не
входит в обязательные зависимости QGIS. Где модуль не установлен (часть
сборок QGIS под Windows, Linux-пакеты без `python3-shapely`, macOS-сборки),
скрипт падает с `ModuleNotFoundError` сразу при запуске, и инструмент клика
даже не создаётся. Используется `shapely` ровно в одном месте:
GeoJSON, затем `shape()`, затем `.wkt`, затем `QgsGeometry.fromWkt()`. Это лишний круг:
QGIS сам читает GeoJSON через `QgsJsonUtils.stringToFeatureList`, а простые
типы геометрии (Point/LineString/Polygon и их Multi-варианты) переводятся в
WKT несколькими строками кода без сторонних библиотек.

### 2.3. Зашитый путь `C:/1` — запись падает

Подтверждено. `output_path = "C:/1/..."`. На macOS и Linux такого пути нет
вообще. На Windows он есть только у того, кто выполнил шаг 1 из README.
Без папки `writeAsVectorFormatV2` возвращает ошибку, и в консоли появляется
`Ошибка записи слоя`: объекты уже скачаны, но записать их некуда.
Каталог нельзя выбрать без правки кода.

### 2.4. `CreateOrOverwriteFile` — пересоздание файла GPKG

Подтверждено (сверх списка). При первом клике в сессии слой создаётся с
`actionOnExistingFile = CreateOrOverwriteFile`. Если файл
`C:/1/NSPD_Kadastr.gpkg` остался от прошлого запуска, он **перезаписывается
целиком**, и всё выгруженное в прошлый раз пропадает. README косвенно об
этом предупреждает («рекомендуется пересохранить файл в другое место»), но
сам скрипт не предупреждает. Если пользователь сложил в этот GPKG свои
слои, они тоже пропадут.

### 2.5. Схема полей задаётся первым кликом — тихая потеря атрибутов

Подтверждено (сверх списка). `result_layer` создаётся один раз, и набор
полей берётся из объектов **первого** ответа. При следующих кликах значения
читаются только по уже существующим полям (`for field in layer.fields()`).
Если у участка из второго клика есть атрибут, которого не было в первом
ответе (другой вид разрешённого использования, другой набор `options`),
значение молча не записывается.

### 2.6. Обрезка имён полей до 63 символов — потеря значений

Подтверждено, причём проблема шире, чем казалось при первичном осмотре.

1. **Коллизии.** `truncate_field_name` просто режет имя до 63 символов. Два
   длинных ключа с одинаковыми первыми 63 символами дают два поля с
   одинаковым именем. GPKG не даст создать второе такое поле, и значение
   одного из атрибутов пропадёт. После `flatten_dict` ключи вида
   `options_..._..._...` вполне могут дорасти до такой длины.
2. **Потеря значения без всякой коллизии.** Значение ищется так:
   `props.get(field.name(), "")`, где `field.name()` — уже **обрезанное**
   имя, а ключи `props` — полные. Для любого атрибута длиннее 63 символов
   поиск не находит ключ, и в поле пишется пустая строка, даже если имя
   уникально.

Кстати, для GeoPackage предела в 63 символа нет. Это предел
PostgreSQL. Обрезка оставлена в новом коде как настройка, чтобы файл
можно было без сюрпризов загрузить в PostGIS.

### 2.7. `FEATURE_COUNT=10` — молчаливая обрезка выдачи

Подтверждено. В запросе стоит жёсткое `FEATURE_COUNT=10`. Если под точкой
клика больше десяти объектов (наложенные ЗОУИТ, многоконтурные участки,
клик на стыке кварталов на мелком масштабе), сервер вернёт не больше
десяти. В консоли будет «Объектов в ответе: 10», и ничто не подскажет, что
это предел запроса, а не реальное число.

### 2.8. Буфер bbox ±100 м независимо от масштаба

Подтверждено, с уточнением про направление эффекта. Запрос строится так:
bbox ±100 м вокруг точки, `WIDTH=HEIGHT=800`, `I=J=400`. Сервер получает
разрешение 0,25 м/пиксель и считает попадание в пикселях этой картинки.
Оно не связано с тем, что пользователь видит на экране:

- **мелкий масштаб** (отдалились, 1:50 000 и мельче, пиксель экрана —
  десятки метров). Bbox ±100 м меньше нескольких пикселей экрана. Клик
  «по участку», который на экране выглядит точным, может оказаться в
  50-100 м от контура, и тогда сервер ничего не находит — **промах**;
- **крупный масштаб** (приблизились, 1:500, пиксель — сантиметры). Bbox
  ±100 м охватывает намного больше, чем видно вокруг курсора. Если сервер
  отбирает объекты по пересечению с bbox или с допуском в пикселях
  запроса, приходят соседние объекты, по которым не кликали —
  **лишнее**.

В исходной формулировке («на мелком ловит лишнее, на крупном
промахивается») направления, по моему расчёту, перепутаны, но причина
одна и та же: bbox не привязан к разрешению карты. Как именно НСПД
отбирает объекты (по bbox целиком или с допуском вокруг I/J), снаружи не
видно, поэтому выраженность каждого эффекта нужно смотреть на живых кликах.

### 2.9. `QEventLoop` без таймаута — QGIS висит

Подтверждено. `loop.exec_()` ждёт только сигнала `finished`. Пока запрос
идёт, интерфейс QGIS не реагирует. Если НСПД не отвечает (перегрузка,
обрыв, блокировка), окно висит, пока не сработает таймаут, заданный в
`Настройки - Параметры - Сеть`. По умолчанию это 60 с, а может стоять и
больше. Сам скрипт времени ожидания не задаёт и не показывает, что запрос
ещё идёт.

К этому же пункту: запрос идёт через свежий `QNetworkAccessManager()`, а
не через `QgsNetworkAccessManager.instance()`. Поэтому настройки прокси и
SSL из параметров QGIS к запросу не применяются. В корпоративной сети с
прокси скрипт может не достучаться до НСПД, хотя сам QGIS его видит.

### 2.10. Ошибка сертификата выглядит невнятно

Подтверждено. Без корневых сертификатов Минцифры (главное требование README)
TLS-рукопожатие с `nspd.gov.ru` не проходит. Скрипт печатает
`Ошибка запроса: <errorString>`, где errorString — системная строка Qt
вроде `SSL handshake failed` или `The issuer certificate of a locally
looked up certificate could not be found`. Из неё не следует, что надо
поставить сертификаты с https://www.gosuslugi.ru/crt и перезагрузить
компьютер. Это главный источник отказов, и сообщение должно прямо
называть причину.

### 2.11. `commitChanges()` на каждый клик — чужая правка сохраняется и закрывается

Подтверждено. Логика в `canvasReleaseEvent`:

```python
if not layer.isEditable():
    layer.startEditing()
...
if layer.commitChanges():
```

Если пользователь сам включил редактирование выходного слоя (например,
удалил лишний участок или поправил атрибут и ещё не сохранил), скрипт
не открывает новую сессию правки, но в конце вызывает `commitChanges()`.
В результате:

- правки пользователя **сохраняются без его ведома**, отменить их через
  «Отменить правки» уже нельзя;
- сессия редактирования **закрывается**, режим правки выключается
  посреди работы.

Сами изменения не теряются, но пользователь теряет контроль над ними.
Если `commitChanges()` вернёт `False`, скрипт выводит только «Ошибка
коммита изменений». Причина (`commitErrors()`) не показывается, и слой
остаётся в режиме правки с недописанным буфером.

### 2.12. Типы геометрии в одном ответе

Подтверждено (сверх списка). Тип слоя определяется по первому объекту с
геометрией (`detect_geom_type`) и больше не меняется. Если в ответе или в
следующем клике придёт объект другого типа (точка в полигональном слое),
`addFeature` вернёт ошибку или QGIS отбросит геометрию. В консоли будет
только «Ошибка добавления объекта N», без причины. Для слоёв из таблицы
это маловероятно, потому что ЗУ и ЗОУИТ полигональные, но обработка
такого случая должна быть явной.

### 2.13. Прочие мелочи

- Весь ответ GetFeatureInfo печатается в консоль (`print(response_text)`).
  Ответ с десятком участков — это сотни килобайт JSON, и консоль QGIS на
  каждом клике заметно тормозит.
- Значения списков (`list`) пишутся через `str()` в Python-нотации
  (`['a', 'b']`), а не JSON. Читается, но парсить такое потом неудобно.
- Код полагается на глобальный `iface` из консоли, поэтому его нельзя
  импортировать как модуль (из плагина или тестов).
- Эмодзи в каждом `print` (галочки, крестики, лупа, мышь, свиток). По
  правилу владельца их быть не должно.
- Завершить работу инструмента можно только выбором другого инструмента
  на панели (шаг 13 README). Явной кнопки «Остановить» нет.

## 3. Порядок исправления и почему

1. **Один скрипт вместо шести** (раздел 1, пункт 2.1). Это делается
   первым, потому что иначе каждое исправление ниже пришлось бы делать
   шесть раз. Код запроса выводится из кода слоя, поэтому опечатка из 2.1
   исчезает сама. Сюда же входят отказ от `shapely` (2.2), выбор пути
   через диалог вместо `C:/1` (2.3) и замена эмодзи текстовыми
   префиксами: без этого новый скрипт не запустится у части
   пользователей. Поведение для пользователя сохраняется: клик добавляет
   объекты в слой, в консоли видно количество.
2. **Починка слабых мест в новом коде.** Сначала пункты, которые теряют
   данные молча: 2.4, 2.5, 2.6, 2.7, 2.11, 2.12. Потом пункты, которые
   мешают работать: 2.9 (таймаут), 2.10 (сертификаты), 2.8 (bbox от
   масштаба). Старые файлы не правятся, они лежат в `legacy/` как есть.
3. **Плагин** поверх той же логики. Общий модуль `nspd_core.py` в
   репозитории существует в одном экземпляре, при сборке zip он
   копируется в пакет плагина.
4. **Совместимость с QGIS 4 (Qt6)** — последним шагом по коду. К этому
   моменту весь новый код уже написан, и перевод делается в одном месте
   (см. раздел 5).
5. **README** — в конце, когда порядок работы окончательно ясен.

Все исправления сделаны в новом коде (`nspd_core.py`, `nspd_parser.py`).
Файлы в `legacy/` не менялись, в них все проблемы остаются как были.

| Пункт | Что сделано |
|---|---|

| 2.2 `shapely` | Убран. Геометрия читается через `QgsJsonUtils.stringToFeatureList`, запасной путь — собственная сборка WKT (Point, LineString, Polygon, их Multi-варианты, GeometryCollection). |

| 2.5 схема по первому клику | Атрибуты, которых нет в слое, добавляются новыми полями (`dataProvider().addAttributes`), и об этом пишется в консоль. Если слой в этот момент в режиме правки, поля не добавляются, а в консоли появляется предупреждение со списком полей. |

| 2.7 `FEATURE_COUNT` | Настраивается (`FEATURE_COUNT` в начале `nspd_parser.py`, по умолчанию 20). Если объектов пришло столько же, сколько запрошено, в консоль выводится предупреждение о возможной обрезке. |
| 2.8 bbox ±100 м | Полуразмер bbox = (метров EPSG:3857 на пиксель экрана в точке клика) × 400, то есть картинка запроса повторяет разрешение карты. Значение ограничено 5 м снизу и 20 км сверху. Если разрешение посчитать не удалось, берётся прежнее значение ±100 м. |
| 2.9 зависание | Таймаут запроса (`TIMEOUT_S`, по умолчанию 30 с). По истечении запрос отменяется, в консоли — понятное сообщение. Запрос идёт через `QgsNetworkAccessManager.instance()` с настройками прокси QGIS. Во время ожидания интерфейс по-прежнему заблокирован: асинхронный запрос — отдельная задача. |
| 2.10 сертификаты | При ошибке рукопожатия TLS или тексте ошибки про SSL, TLS или сертификат к сообщению добавляется подсказка про сертификаты Минцифры со ссылкой https://www.gosuslugi.ru/crt. |
| 2.11 `commitChanges()` | Если слой уже был в режиме правки у пользователя, объекты добавляются в его правку без сохранения, и в консоль выводится предупреждение. Если правку открыл скрипт, он её и закрывает. При ошибке сохранения выводится `commitErrors()` и правка откатывается. |
| 2.12 типы геометрии | Объект, тип геометрии которого не совпадает с типом слоя, пропускается с сообщением, в котором названы оба типа. |
| 2.13 мелочи | Полный ответ сервера в консоль не печатается. Списки сохраняются как JSON. Общий модуль не зависит от глобального `iface`. Эмодзи заменены префиксами `NSPD:`, `NSPD [внимание]:`, `NSPD [ошибка]:`. В плагине есть явная кнопка «Остановить»; в скрипте, как и раньше, работа заканчивается выбором другого инструмента. |

## 5. Изменения ради QGIS 4 (Qt6)

QGIS 4 собирается на Qt6 и PyQt6. Ниже то, что в новом коде (`nspd_core.py`,
`nspd_parser.py`, `plugin/`) сделано ради работы и в QGIS 3.x, и в QGIS 4,
и почему. Места, где API различается, собраны в блоке «Совместимость» в
начале `nspd_core.py`, скрипт и плагин пользуются им же.

| Было | Стало | Почему |
|---|---|---|
| `from PyQt5.QtCore import QVariant` (старые скрипты) | Qt импортируется только через `qgis.PyQt.*`, прямого `PyQt5` нет нигде | `qgis.PyQt` — прослойка QGIS: в QGIS 3 она отдаёт PyQt5, в QGIS 4 — PyQt6. Прямой `import PyQt5` в QGIS 4 падает с `ModuleNotFoundError`. |
| `QgsField(name, QVariant.String)` | `QgsField(name, string_field_type())`: сначала `QMetaType.Type.QString`, откат на `QVariant.String` | В Qt6 перечисления `QVariant.Type` нет. QGIS 3.38+ принимает в `QgsField` тип `QMetaType.Type`, QGIS 4 — только его, QGIS до 3.38 — только `QVariant.Type`. Подходящий вариант выбирается один раз пробным созданием поля. |
| `loop.exec_()` | `exec_event_loop(loop)`, внутри `loop.exec()` | В PyQt6 метода `exec_()` нет. Запасной `exec_()` берётся, только если `exec()` отсутствует. |
| `if reply.error():` | `if reply.error() != qt_enum(QNetworkReply, "NetworkError", "NoError")` | В PyQt5 `NoError` равен 0 и ложен. В PyQt6 члены перечислений — объекты `enum`, и `NoError` **истинен**. Старая проверка в QGIS 4 считала бы ошибкой каждый успешный ответ. |
| `QNetworkReply.SslHandshakeFailedError`, `QgsVectorFileWriter.NoError`, `.CreateOrOverwriteFile`, `.CreateOrOverwriteLayer`, `Qt.RightDockWidgetArea`, `QFileDialog.DontConfirmOverwrite` | `qt_enum(владелец, "Перечисление", "Член")`, например `qt_enum(Qt, "DockWidgetArea", "RightDockWidgetArea")` | В PyQt6 члены перечислений доступны только через класс перечисления (`QFileDialog.Option.DontConfirmOverwrite`). `qt_enum` сначала берёт полную форму, потом короткую. |
| `QgsVectorFileWriter.writeAsVectorFormatV2` | `write_vector_layer()`: `writeAsVectorFormatV3`, откат на V2 | V2 устарел с QGIS 3.20, V3 есть с 3.20. На наличие V2 в QGIS 4 рассчитывать нельзя, а откат нужен для QGIS 3.16-3.18. |
| `QgsJsonUtils.stringToFeatureList(text, fields, encoding)` | Сначала вызов с одной строкой, затем с `QgsFields()`, затем с `None` | Третий аргумент в QGIS 3 имел тип `QTextCodec`, которого в Qt6 нет. Вызов без него работает в обоих вариантах API. |
| `self.toMapCoordinates(event.pos())` | `event.mapPoint()`, запасной путь — прежний | В Qt6 `QMouseEvent.pos()` объявлен устаревшим в пользу `position()`. `QgsMapMouseEvent.mapPoint()` сразу даёт точку в координатах карты и от Qt не зависит. |
| `reply.readAll().data()` | `bytes(reply.readAll())` | Одинаково работает для `QByteArray` в PyQt5 и PyQt6. |
| `from qgis.PyQt.QtWidgets import QAction` | `QAction` из `QtGui`, откат на `QtWidgets` | В Qt6 `QAction` переехал из `QtWidgets` в `QtGui`. |
| `QgsWkbTypes.displayString(layer.wkbType())` | То же, но в `try`. Если вызов не сработал, проверка типа геометрии отключается, а не ломает запись. | Перечисления геометрии в QGIS 3.30+ переехали в `Qgis.WkbType`. Вспомогательный `QgsWkbTypes` пока остаётся, но страховка дешёвая. |
| В `metadata.txt` нет `qgisMaximumVersion` | `qgisMaximumVersion=4.99`, `supportsQt6=True` | Без явного максимума QGIS берёт пределом `3.99` и считает плагин несовместимым с QGIS 4. `supportsQt6` — признак, который QGIS проверяет для Qt6-сборок. |
| Глобальный `iface` из консоли | Общий модуль получает `canvas` явно, скрипт берёт `iface` из `qgis.utils` | Не связано с Qt6, но без этого общий модуль нельзя импортировать из плагина. |

Не трогали: адрес API НСПД (`/api/aeggis/v3/`). «Версия 4» относится к
QGIS, а не к API.

Как это проверено. Синтаксис — `python -m py_compile` по всем новым
файлам. Отсутствие `PyQt5`, `shapely` и эмодзи — поиском по тексту.
Ветвления слоя совместимости (`qt_enum`, `exec_event_loop`,
`string_field_type`, `write_vector_layer`, обработка ответа и ошибок
запроса) прогнаны на подделках, повторяющих поведение PyQt5 и PyQt6,
в том числе на истинном `NoError` из PyQt6. В живом QGIS 3 и QGIS 4 код
не запускался. Таблица составлена по документации API QGIS и списку
изменений Qt6, поэтому первое, что нужно сделать в QGIS 4, — пройти
шаги ручной проверки из описания PR.
